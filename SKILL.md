# shell-auto_complete

A Crystal shard that turns a single macro-DSL command definition into three
things at once: an argument **parser**, a `--help` renderer, and **shell
completion** scripts for bash, zsh, and fish. Completions can call back into the
binary for dynamic candidates.

- Module namespace: `Shell::AutoComplete`
- Entry point: `require "shell-auto_complete"`
- Crystal `>= 1.20.1`

## When to use this skill

Use it whenever you are authoring or editing a Crystal CLI built on this shard.
Concretely: defining commands, flags, positionals, or subcommands; choosing or
writing a value type; adding validation, custom transforms, or dynamic
completion; or setting up the `--shell-completion` install path.

## Mental model

Every command is a subclass of `Shell::AutoComplete::Command`, generated by the
`Shell::AutoComplete.command` macro. Inside the block you declare `flag`,
`positional`, `positionals`, and `subcommand`. Each flag/positional becomes a
**property** on the instance, so `run` reads its values as `@name` or `name`.

The macros emit annotations (`FlagDef`, `PositionalDef`, etc.) that the base
class reads at compile time to build the parser, help text, and completion
candidates. There is no runtime config object — everything is derived from the
declarations.

Values are converted from strings via a `__arg_transform` class method on the
target type and checked via `__arg_validate`. The shard ships these for all the
common stdlib and numeric types; you override per flag with `transform_with:` /
`validate_with:` when you need custom behavior.

## Minimal command

```crystal
require "shell-auto_complete"

Shell::AutoComplete.command Greet, name: "greet", description: "Greet someone" do
  flag loud : Bool = false, "--loud", "-l", "Shout the greeting"
  positional who : String, "Name to greet"

  def run
    msg = "Hello, #{who}!"
    puts loud ? msg.upcase : msg
  end
end

Greet.dispatch(ARGV)
```

`Command.dispatch(ARGV)` is the single call that runs everything: it intercepts
completion requests and `--help`, routes subcommands, parses, then calls `run`.

## The `command` macro

```crystal
Shell::AutoComplete.command TypeName, name: "cli-name", description: "...", **opts do
  # flag / positional / positionals / subcommand declarations
  # def run ... end
end
```

- `TypeName` — the Crystal class to define (a `Command` subclass).
- `name:` — the command/subcommand name shown in help and completion. If
  omitted, defaults to `File.basename(PROGRAM_NAME)`.
- `description:` — one-line summary for help and parent subcommand lists.
- Optional help overrides forwarded to the renderer: `header:`, `footer:`,
  `usage:` (all `String`).

Define `def run` for any command that does work. Commands that only route to
subcommands don't need `run` — they print help when called with no args.

## The `flag` macro

```crystal
flag decl, *flag_strings, **opts
```

- `decl` is a Crystal var-with-type, e.g. `verbose : Bool = false` or
  `port : Int32?`. The type drives parsing; the optional default sets the
  initial property value.
- `flag_strings` are string literals: long forms (`--foo`), at most one short
  form (`-f`), and a description. You may pass them inline or grouped in an
  array literal — both work:

```crystal
flag message : String?, "--message", "--msg", "-m", "Build message"
flag message : String?, %w(--message --msg -m), "Build message"
```

The first long form is canonical; the rest are aliases. **Reserved names** that
will raise at compile time: `--help`, `-h`, `--all-help`, and the
shell-completion flag (default `--shell-completion`).

### Flag types and parsing behavior

- **`Bool`** — a switch (no value). A `Bool` flag is negatable by default:
  `--foo` sets true, `--no-foo` sets false. Disable with `negatable: false`.
- **Scalars** — `Int8`..`Int64`, `UInt8`..`UInt64`, `Float32/64`, `String`,
  `Char`, and stdlib types below. Use a nilable type (`Int32?`) for "unset", or
  give a default. `bare_number: true` adds the `head -20` shape as another
  spelling of the same flag (`{sign: :plus}` for `+50`, `keep_sign:`,
  `suffix:`, or a `pattern:`/`label:` pair for any other shape).
- **Enums** — `flag level : LogLevel = LogLevel::Info, ...`. Pass a case name.
  Add `shortcut_flags: true` to also generate per-case switches
  (`--debug`, `--info`, …). Not allowed on `@[Flags]` enums.
  Configure with `{only:/except:/shorts:/aliases:}`: `shorts: {info: "-v"}`
  gives a case switch a short spelling, `aliases: {quiet: :warn}` adds a named
  switch, and an alias key or value may spell the switch itself —
  `aliases: {"-q": :warn}` or `aliases: {quiet: {value: :warn, short: "-q"}}`.
- **`@[Flags]` enums** — comma-separated values (`--perms read,write`).
  Completion is trailing-comma aware. `shortcut_flags` is rejected here.
- **Collections** — `Array(T)`, `Set(T)`, `Hash(String, T)`. Repeatable and/or
  comma-delimited (control the split with `delimiter:`, or `delimiter: nil` to
  keep whole values). Provide an empty default, e.g.
  `flag tags : Array(String) = [] of String, ...`.
  - `Set(T)` with `set_operations: true` accepts `+x` / `-x` prefixes to add or
    remove members across repeats.
  - `Hash(String, T)` takes `KEY=VALUE`; `-KEY` deletes a key.

### Built-in validation options (forwarded to `__arg_validate`)

Any opt that isn't a known keyword is forwarded to the type's transform/validate
methods. The bundled types understand:

- `range:` — numeric types, e.g. `flag port : Int32?, "--port", range: 1..65535`.
- `matches:` — `String`, a `Regex`.
- `choices:` — `String`, an array of allowed values.

### Custom transform / validate / complete (per flag)

Point these at `self.`-level class methods defined in the same command block:

```crystal
flag region : String = "", "--region", "-r", "AWS region",
  validate_with: :validate_region,
  complete_with: :complete_region

flag duration : Int32 = 600, "--duration", "-d", "Timeout (30s, 5m, 2h)",
  transform_with: :transform_duration

def self.validate_region(value : String) : Bool | String
  ALLOWED.includes?(value) ? true : "must be one of #{ALLOWED.join(", ")}"
end

def self.transform_duration(value : String) : Int32
  # ... parse "5m" -> 300 ; raise ArgumentError on bad input
end

def self.complete_region(ctx : Shell::AutoComplete::CompletionContext) : Array(String)
  ALLOWED
end
```

- `transform_with:` — `(String) -> T`. Raise `ArgumentError` on bad input (it is
  converted to a clean parse error).
- `validate_with:` — `(T) -> Bool | String`. Return `true` for ok, or an error
  message string. `false` yields a generic "not a valid …" message.
- `complete_with:` — `(CompletionContext) -> Array(String)`. Called by the shell
  to produce dynamic candidates for this flag's value. `CompletionContext`
  exposes `words`, `cword`, `current_word`, and `prior_words`.

Per-flag instance methods named `__arg_transform_<name>`,
`__arg_validate_<name>`, `__arg_complete_<name>` are also picked up if present,
taking precedence over the `*_with:` options.

**Union types** (other than `T?`) require an explicit `transform_with:`.

### Other flag opts

- `hidden: true` — omit from help and completion (still parses).
- `negatable:` — `Bool` only; default `true`.

## Positionals

```crystal
positional name : String, "Build name"          # required (non-nilable)
positional tag : String?, "Optional tag"         # optional (nilable)
positionals files : Array(Path), "Sources", min: 1, max: 10
```

- `positional` — a single argument. Non-nilable types are required and generate
  a `property!` (raises if accessed unset); nilable types are optional.
- `positionals` — one variadic bucket per command, typed `Array(T)`, `Set(T)`,
  or `Hash(String, T)`. `min:` / `max:` bound the count. Leading required
  positionals, then the variadic bucket, then trailing positionals are filled in
  order.
- Both accept `transform_with:`, `validate_with:`, `complete_with:`, `hidden:`.
- **A command cannot have both `positional`/`positionals` and `subcommand`.**

## Subcommands

Define each subcommand as its own `command`, then register children by class:

```crystal
Shell::AutoComplete.command AppScan, name: "scan", description: "..." do
  flag deep : Bool = false, "--deep", "Thorough scan"
  def run; ...; end
end

Shell::AutoComplete.command App, name: "app", description: "..." do
  subcommand AppScan
  subcommand AppBuild
end

App.dispatch(ARGV)
```

Nesting is arbitrary — a subcommand may itself register subcommands. A routing
command with no `run` prints its help when invoked bare. `--all-help` on a
command with subcommands prints the whole tree.

## Dispatch, help, and errors

`Command.dispatch(argv, stdout = STDOUT, stderr = STDERR, rescue_errors = true)`:

1. Handles a completion request (shell calling back) if present.
2. Handles `--shell-completion <shell>` install output.
3. Routes to a matching subcommand.
4. Prints help for bare routing commands, `--all-help`, or `--help`/`-h`.
5. Otherwise parses argv and calls `run`.

With `rescue_errors: true` (default), a `ParseError` is printed as
`command-path: message` to stderr and the process exits 1. Pass
`rescue_errors: false` to let exceptions propagate (useful in specs). The error
hierarchy: `Shell::AutoComplete::Error` → `ParseError` (has `command_path`),
`NotRunnable`, `SystemExit`.

## Shell completion

The binary emits its own completion script:

```sh
# Bash — eval in .bashrc, or write to a completions dir
eval "$(mycli --shell-completion bash)"

# Zsh — write to a file on the fpath
mycli --shell-completion zsh > _mycli

# Fish
mycli --shell-completion fish > ~/.config/fish/completions/mycli.fish
```

Completion covers subcommand names, flag names (with smart alias filtering —
aliases surface only when the canonical form doesn't match the typed prefix),
`@[Flags]` enum members with trailing-comma awareness, and any
`complete_with:` dynamic candidates.

## Value types reference

Built-in transformers/validators ship for:

- Numerics: `Int8`–`Int64`, `UInt8`–`UInt64`, `Float32`, `Float64` (`range:`).
- `String` (`matches:`, `choices:`), `Char`, `Bool`.
- stdlib: `Path`, `URI`, `Time`, `Regex`, `Log::Severity`, `Socket::IPAddress`,
  `File`/`Dir` (transform to `Path`).
- Enums (incl. `@[Flags]`), `Array(T)`, `Set(T)`, `Hash(String, T)`.
- Synthetic types under `Shell::AutoComplete::Types`: `PositiveInt`,
  `NonNegativeInt`, `Percentage`, `EpochTime`, `Date`, `EnvVar`. Use them via
  `transform_with:`/`validate_with:` wrappers calling `Type.__arg_transform` /
  `Type.__arg_validate` (see `examples/multitool/multitool.cr`).

### Adding your own type

Define class methods on the type so the macros can find them:

```crystal
struct MyId
  def self.__arg_transform(value : String, **opts) : MyId
    # parse; raise ArgumentError on bad input
  end

  def self.__arg_validate(value : MyId, **opts) : Bool | String
    true  # or an error message string
  end
end
```

If `__arg_transform` returns a different base type than declared (e.g.
`File` → `Path`), the property is stored as the returned type automatically.
